📁 Active Directory
i
Active Directory ist wie ein zentrales Adressbuch + Regelwerk für ein ganzes Firmennetzwerk: es weiss, wer (Benutzer), was (Computer), wo (Organisationseinheiten) ist, und welche Regeln (Gruppenrichtlinien) wo gelten.

🖥️ Praxislabor Teil 2: SRV01 zum Domänencontroller befördern
i
Ein Domänencontroller ist einfach ein Server, auf dem zusätzlich die Active-Directory-Domänendienste laufen - genau der DHCP-/DNS- Server aus dem vorherigen Labor wird jetzt zum "Adressbuch + Regelwerk" für die ganze (kleine) Testumgebung.

Baut direkt auf dem Praxislabor im Modul DNS-Auflösung & DHCP-Prozess auf: denselben Server (SRV01) mit DHCP+DNS verwenden, nicht neu aufsetzen - genau das ist der Punkt, DHCP/DNS und Active Directory laufen in echten Firmennetzen fast immer auf demselben Server(-typ).

Schritt für Schritt

  1. Auf SRV01 die Rolle Active Directory-Domänendienste (AD DS) installieren (Server-Manager → Rollen hinzufügen, oder per PowerShell: Install-WindowsFeature AD-Domain-Services -IncludeManagementTools). Anleitung: Microsoft Learn - AD DS installieren
  2. Server zum Domänencontroller heraufstufen (im Server-Manager über das Benachrichtigungs-Flag, oder Install-ADDSForest): neue Gesamtstruktur, als Stammdomänenname genau die DNS-Zone von vorhin verwenden (lab.local) - dann passt die vorhandene DNS-Zone direkt zur neuen Domäne. Ein DSRM-Wiederherstellungskennwort setzen (merken!) und den abschliessenden Neustart abwarten.
  3. Auf CL01 (dem Client aus Labor 1) der Domäne beitreten: Systemsteuerung → System → "Domäne oder Arbeitsgruppe ändern" → Domäne lab.local eingeben, mit dem Domänen-Administrator-Konto bestätigen, neu starten.
  4. Auf CL01 mit dem Domänenkonto anmelden und per whoami /fqdn die volle Domänen-Identität prüfen.
  5. Auf SRV01 in "Active Directory-Benutzer und -Computer" nachsehen: CL01 sollte jetzt im Container Computers auftauchen.
  6. Optional weiterführend: einen Testbenutzer sowie eine OU mit eigener GPO anlegen und live nachvollziehen, was du im LSDOU-Quiz weiter unten theoretisch durchgespielt hast.
Wichtige Reihenfolge: DHCP/DNS MUSS vor der Beförderung zum Domänencontroller funktionieren - AD DS braucht zwingend einen funktionierenden DNS-Server, um sich selbst einzutragen. Falls die Beförderung mit einem DNS-Fehler abbricht, zurück zu Labor 1 und die DNS-Rolle/Zone prüfen.

Fortschritt

AD-Objekte auf einen Blick

  • Benutzer/Computer-Objekte: repräsentieren Personen bzw. Geräte in der Domäne, jeweils mit eigener eindeutiger SID.
  • Organisationseinheiten (OUs): Container zur Strukturierung (z.B. nach Abteilung/Standort) - wichtigster Ankerpunkt für Gruppenrichtlinien und delegierte Verwaltung.
  • Sicherheitsgruppen: fassen Objekte für Berechtigungen zusammen (z.B. Dateifreigaben, GPO-Filterung). Verteilergruppen hingegen sind nur für E-Mail-Verteilerlisten gedacht und tragen keine Berechtigungen.

Gruppenrichtlinien-Vererbung (LSDOU)

Gruppenrichtlinien (GPOs) werden in der Reihenfolge Local → Site → Domain → OU verarbeitet, wobei später verarbeitete Einstellungen früher verarbeitete überschreiben (die nächstgelegene OU "gewinnt" bei Konflikten). Zwei Sonderregeln durchbrechen das:

  • Vererbung blockieren (Block Inheritance): eine OU kann die Vererbung von GPOs aus höher liegenden Ebenen unterbinden.
  • Erzwungen (Enforced): ein GPO kann so gesetzt werden, dass es sich IMMER durchsetzt - auch gegen "Block Inheritance" weiter unten im Baum.

Wichtig: Vererbung wirkt nur top-down entlang der eigenen Astlinie - ein GPO an einer OU wirkt nie auf einen komplett anderen Zweig des Baums.
